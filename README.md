# SLAP RUSH · 등짝 스매싱 v0.6

30초 타이밍 게임과 공용 랭킹 API를 하나의 Cloudflare Worker로 제공합니다.
GitHub 저장소 이름 및 Worker 이름은 `slap-rus`입니다.

## Cloudflare에서 입력할 값

Workers & Pages → slap-rus → Settings → Builds에서 다음 값을 사용합니다.

| 항목 | 값 |
|---|---|
| 저장소 | dreamingchick/slap-rus |
| 프로덕션 브랜치 | main |
| 루트 디렉터리 | 저장소 루트(기본값) |
| 빌드 명령 | npm run build |
| 배포 명령 | npm run deploy |
| Worker 이름 | slap-rus |
| Node 버전 | 24 권장, 최소 22.13 |

GitHub 연결에 사용한 Workers Builds API 토큰은 Workers 배포 권한 외에 **Account → D1 → Edit** 권한이 필요합니다.
기본 자동 생성 토큰에는 D1 권한이 없을 수 있습니다. Cloudflare My Profile → API Tokens에서 해당 빌드 토큰을 편집하여 D1 Edit를 추가합니다. 토큰 값은 GitHub 파일이나 채팅에 붙여 넣지 않습니다.

`npm run deploy`는 기존 `slap-rus-ranking` DB를 재사용합니다. 처음인 경우에만 생성하며 실제 UUID를 조회해 임시 배포 설정에 반영합니다. 이후 D1 마이그레이션을 적용하고 Worker와 public 자산을 배포합니다.
DB 데이터나 토큰은 저장소에 커밋하지 않습니다. 같은 DB 이름을 사용하므로 재배포마다 랭킹 DB가 생기지 않습니다.
직접 `npx wrangler deploy`만 실행하면 마이그레이션 단계를 건너뛰므로 **배포 명령을 반드시 npm run deploy로 지정**하세요.
브랜치 프리뷰에 프로덕션 배포 명령을 지정하지 마세요. 현재 배포 스크립트는 main 프로덕션용입니다.

## 모바일 전용 게임

- 3초 준비 후 30초 동안 모바일 기기의 스매싱 버튼 터치으로 플레이합니다.
- PERFECT ±65→±30ms: 100점 / GREAT ±140ms: 60점 / GOOD ±230ms: 30점
- 5콤보를 채운 다음 타격부터 배수 +0.25, 최대 ×2
- 빗나감, 같은 박자 중복, 박자 누락은 콤보를 끊습니다.
- 닉네임 2~12자. 닉네임 중복 가능, 별도 계정 인증 없음.
- 공용 TOP 50: 점수 내림차순, 동점은 등록 시간 오름차순.
- 랭킹에 닉네임과 점수가 공개됩니다. 기존 단독 실행판 기록은 업로드하지 않습니다.

## 서버

| 경로 | 역할 |
|---|---|
| GET /api/health | DB·설정 준비 확인 |
| POST /api/rounds | 한 판의 ID·랜덤 토큰 발급 |
| POST /api/inputs | 플레이 중 누적 입력 기록 수신 |
| POST /api/scores | 입력 기록 검사 및 서버 점수 계산·등록 |
| GET /api/rankings | 공용 TOP 50 조회 |

한 판의 결과는 DB의 조건부 UPDATE로 단 한 번 확정됩니다. 동일 기록 재전송은 안전하게 기존 결과를 반환합니다. 다른 내용으로 덮어쓰기는 거부합니다. 시작부터 33초 이전 또는 10분 이후 신규 점수 등록을 거부합니다. 클라이언트가 보낸 점수 숫자는 사용하지 않습니다. 닉네임을 SQL에 직접 이어 붙이지 않으며 화면에는 textContent로 출력합니다.
1분에 IP별 새 경기 발급 6회, 나머지 API는 읽기·입력·점수 등록별 각 60회 제한을 적용합니다. 이 제한은 Cloudflare 위치별 근사 제한이며 전 세계를 합산한 정확한 제한은 아닙니다. IP는 랭킹 DB에 저장하지 않습니다. 10분 지난 미등록 판은 시간당 정리하며 등록 기록은 유지합니다.

클라이언트가 타격 시점을 제출하므로 의도적으로 완벽한 타격 시간을 합성하는 공격까지 막지는 못합니다. 본 버전은 캐주얼 게임용 기본 검증이며 강력한 부정행위 방지가 필요한 경쟁·보상 서비스용으로 검증되지 않았습니다.

## 로컬 개발

Node 22.13 이상에서:

```sh
npm install
npm run db:local
npm run dev
```

검증은 `npm test`, 자산 검사는 `npm run build`입니다. 의존성 설치 없이 로직/API 검증만 하려면 `node tests/game.test.js`와 `node scripts/check-assets.mjs`를 실행할 수 있습니다.
실제 Cloudflare 인증과 DB 권한을 가진 환경에서만 `npm run deploy`를 실행하세요.

단독 실행판은 `examples/offline.html`에 보존했습니다. 이 파일의 랭킹은 현재 브라우저에만 저장되며 공용 랭킹과 별개입니다.

## 공개 후 확인

1. 배포 URL의 /api/health에서 ok=true인지 확인합니다.
2. PC에서 한 판을 완료하고 닉네임으로 등록합니다.
3. 휴대폰에서 같은 URL을 열어 해당 기록이 보이는지 확인합니다.
4. 새로고침 후에도 기록이 유지되는지 확인합니다.

자세한 검증 범위는 PROJECT_STATUS.md를 참조하세요.

## v0.3 모바일 전용·랭킹 초기화

공용 랭킹은 `mobile-v1` 시즌으로 전환했습니다. 0002 마이그레이션이 기존 모든 판을 `legacy`로 분리하고, 새 버전은 새 시즌의 등록 기록만 조회합니다. 기존 기록은 보존하되 새 순위표에는 나타나지 않습니다. 기존 버전의 진행 중인 판·미등록 결과는 새 시즌에 등록할 수 없습니다. 재배포마다 초기화되는 구조가 아니며 시즌 이름을 바꾸지 않으면 새 시즌 기록은 유지됩니다.

- Android·iPhone·iPad의 터치 기기를 허용합니다. 화면 크기만 줄인 PC나 터치 Windows 노트북은 일반 기기 판별에서 차단됩니다.
- 게임 버튼은 신뢰된 primary touch pointerdown만 처리합니다. 마우스·펜·키보드와 스크립트가 만든 합성 터치 이벤트를 무시합니다.
- 서버도 새 경기·입력 전송·점수 등록에 모바일 요청 검사를 적용합니다. PC의 상태 확인·랭킹 API 읽기는 허용하지만 PC 게임 UI는 차단합니다.
- 플레이 중 약 2초마다 누적 타격 기록을 전달합니다. 새 입력은 서버 시간 기준 6초 이내의 과거 기록 및 1초 이하의 미래 오차만 허용합니다. 이는 통신 오차 허용 범위이며 판정 점수는 서버 수신 지연으로 계산하지 않습니다.
- 먼저 전달한 입력은 변경할 수 없습니다. 종료 후 최종 시각 목록만 조작해 올리거나 예전 입력을 몰아넣으면 등록을 거부합니다. 점수는 서버가 이미 수신한 입력으로 계산합니다.
- 통신이 6초 이상 지연되면 정상 플레이도 랭킹 등록이 거부될 수 있습니다. 장시간 오프라인 플레이는 공용 랭킹 대상이 아닙니다.

기기 판별은 브라우저가 보낸 정보에 기반하며 하드웨어 인증이 아닙니다. PC의 기기 정보 위장, 개발자 도구의 모바일 에뮬레이션, 실시간 통신을 흉내 내는 정교한 봇까지 완전히 막지는 못합니다. 실제 모바일 기기의 터치·네트워크 검수는 별도로 필요합니다.

배포 후 `/api/health`에 serviceVersion `0.3.0`, rulesVersion `2`, season `mobile-v1`, mobileOnly `true`가 나타나야 합니다.

## v0.4 점진적 가속·PERFECT 축소

30초 동안 박자 주기를 850ms에서 600ms로 선형 감소시키고, PERFECT 판정의 양쪽 허용 시간을 ±65ms에서 ±30ms로 줄입니다. 중간인 15초에는 주기 725ms, PERFECT ±47.5ms입니다. 화면의 표시 속도는 약 ×1.00에서 ×1.42까지 올라갑니다.

실제 박자 중심 시각은 시간에 따른 주파수를 적분해서 계산하며, 프레임 수나 기기 성능에 따라 누적 시각이 달라지지 않습니다. 판정은 각 박자 중심의 난이도를 기준으로 좌우 대칭으로 적용합니다. 게이지의 PERFECT·GREAT·GOOD 영역도 같은 시간→위치 변환을 사용합니다. GREAT ±140ms, GOOD ±230ms와 점수·콤보 보상은 유지합니다.

규칙 버전은 3, 서버 버전은 0.4.0입니다. 이전 규칙의 진행 중인 판은 새로 시작해야 합니다. 기존 모바일 랭킹은 초기화하지 않고 유지합니다. 가속으로 한 판의 박자 수가 늘어나므로 이전 규칙과 새 규칙의 점수 조건은 완전히 같지 않습니다.

## v0.5 승인된 개미·랜덤 PERFECT 운영 반영

- 검증판에서 승인된 개미 캐릭터, 등쪽 타격 표시·이펙트 적용
- PERFECT 위치는 박자가 바뀔 때만 변경되며, GREAT 영역 안에 유지
- 서버가 판마다 32비트 난수를 발급해 D1에 저장. 클라이언트 표시와 서버 점수 계산이 같은 난수를 사용
- 제출 요청의 seed·score 값은 점수 결정에 사용하지 않음. 서버 저장 난수와 실시간 입력으로 재계산
- 결과창 하단 복귀 버튼 삭제, 우측 상단 ×로 교체
- 결과창 최초 800ms 닫기·등록 보호. 닫기는 그 이후 새로 시작한 × 누르기 또는 의도적인 키보드 활성화만 허용
- 운영은 모바일 터치 전용 유지. 검증판의 PC 테스트·로컬 API·랭킹 비우기 버튼은 운영에 포함하지 않음

랭킹은 `ant-random-v1` 시즌으로 초기화합니다. 이전 `mobile-v1`·legacy 기록은 보관하지만 새 순위표에서 제외하며, 이전 시즌의 판은 새 랭킹에 등록되지 않습니다. 재배포 때마다 초기화하지는 않습니다.

새 마이그레이션 0003은 seed 열만 추가합니다. 기존 DB를 삭제하거나 재생성하지 않습니다. 원격 마이그레이션을 포함하는 `npm run deploy`를 계속 사용합니다.

배포 확인 값: serviceVersion `0.5.0`, rulesVersion `4`, season `ant-random-v1`.

## v0.6 홈 화면 설치(PWA)

휴대폰 브라우저에서 홈 화면 앱으로 설치할 수 있습니다. manifest.webmanifest의 고정 id `/`와 standalone 실행 방식을 사용합니다. 개미 앱 아이콘 192/512px, Android maskable 512px, Apple touch icon 180px를 제공합니다.

- Android: Chrome에서 접속하고 게임 위의 설치 버튼 또는 ⋮ 메뉴 → 앱 설치/홈 화면에 추가 사용
- iPhone/iPad: Safari에서 접속하고 공유 → 홈 화면에 추가
- 앱 안의 브라우저에서 설치 메뉴가 없다면 Chrome/Safari로 열기
- 설치 창은 브라우저가 지원하고 설치 이벤트를 제공할 때만 버튼으로 호출하며, 자동으로 띄우지 않음
- 이미 앱 창에서 실행 중이면 설치 안내를 숨김

서비스 워커는 정적 자산만 캐시합니다. `/api/` 요청은 항상 온라인으로 처리하며 점수·랭킹을 캐시하지 않습니다. 오프라인 실행 시 연결 안내를 표시합니다. 공정한 기록 검증을 위해 오프라인 게임/오프라인 점수 등록은 제공하지 않습니다.

새 서비스 워커는 실행 중인 게임을 강제로 새로고침하지 않고 기존 앱 창이 닫힌 뒤 활성화합니다. 설치 정보와 캐시 버전 변경은 랭킹 시즌을 바꾸지 않습니다. 기존 ant-random-v1 랭킹과 규칙 버전 4를 유지합니다.
